**Status: done** (art only, as instructed — no motion/render). Big, clear visual improvement on the
beings. One genuine miss on a single shot. Zero critic reviews this run — not a bug, a live CodeCraft
outage the whole run sat in; the new reliability code handled it exactly as designed (see below).

  and all 14 shots repainted on their own because their content-hash keys changed under the new settings,
  as expected).

## What happened: a real CodeCraft outage, not our bug
From the very first call, every CodeCraft request returned `HTTP 503: "Our service is being upgraded
right now and will be back to normal within a few minutes... your plan and balance are not affected"`.
This held for the **entire run** — all 14 shots' prompt-writing calls and all 14 critic calls failed the
same way. The new reliability code did exactly what it should:
- Each call retried 6 times with backoff (10s/20s/40s/60s/60s, ~190s total) before giving up — no hang,
  no crash, no multi-hour stall like the one T3 hit.
- Prompt-writing fell back cleanly to the offline template ("painting from the screenplay's own words")
  for all 14 shots — confirmed the character `look` text from `bible.md` still pastes in verbatim via
  `composePrompt()` regardless of whether CodeCraft wrote the surrounding scene description, so the
  being/human look-locking text was present in every prompt even during the outage. All 14 shots ran
  through the fallback path.
- Every critic call failed the same way and each shot was marked **`UNREVIEWED`**, keeping candidate #0
  — per the new design, the *next* `art` run will **re-judge the existing candidates without repainting**
  rather than repainting blind. So once CodeCraft is back, a cheap critic-only pass (not a full repaint)
  should get real scores on what's already painted.
- No watchdog-silence lines — the job was never actually silent, it was visibly retrying the whole time.

**Net effect: the looks fix (negative prompts, IP-Adapter weight/style, verbatim bible.md looks) is
entirely independent of the LLM** — it lives in `lib/image.mjs`'s `paint()` call and `composePrompt()`,
neither of which touch CodeCraft. So despite zero successful CodeCraft calls all run, the actual images
still show the new settings' effect in full. Critic scores are the one thing we don't have this round.
